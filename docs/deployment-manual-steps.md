# Deployment — Manual Steps

Checklist of tasks that require human action (accounts, secrets, assets, external services). Complete these before or shortly after deploying to Vercel.

---

## 1. Environment Variables on Vercel

Go to **Project Settings → Environment Variables** and add:

| Variable | Value / Source |
|---|---|
| `NEXT_PUBLIC_SANITY_PROJECT_ID` | `apggi8zn` |
| `NEXT_PUBLIC_SANITY_DATASET` | `production` |
| `SANITY_API_READ_TOKEN` | Sanity dashboard → API → Tokens (viewer role) |
| `SANITY_REVALIDATE_SECRET` | Generate: `openssl rand -base64 32` |
| `SANITY_PREVIEW_SECRET` | Generate: `openssl rand -base64 32` |
| `AMPRE_API_BASE_URL` | AMPRE OData endpoint |
| `AMPRE_API_TOKEN` | AMPRE bearer token |
| `CRON_SECRET` | Auto-generated by Vercel when Cron Jobs are enabled |
| `UPSTASH_REDIS_REST_URL` | Upstash dashboard → Redis → REST URL |
| `UPSTASH_REDIS_REST_TOKEN` | Upstash dashboard → Redis → REST Token |
| `RESEND_API_KEY` | resend.com → API Keys |
| `RESEND_FROM_EMAIL` | Verified sender address (e.g. `Drenova Group <noreply@drenovagroup.com>`) |
| `CONTACT_EMAIL` | Inbox for form submissions (e.g. `info@drenovagroup.com`) |
| `NEXT_PUBLIC_SITE_URL` | Production URL (e.g. `https://drenovagroup.com`) |

---

## 2. Resend Email Setup

The contact form uses [Resend](https://resend.com) to deliver submissions.

1. Create a Resend account at resend.com
2. Add and verify your sending domain (`drenovagroup.com`)
3. Create an API key
4. Set `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, and `CONTACT_EMAIL` in Vercel env vars

Free tier: 100 emails/day, 3,000/month.

## 4. Sanity Webhook (ISR Revalidation)

Configure so content changes in Sanity automatically refresh the site.

1. Go to [sanity.io/manage](https://sanity.io/manage) → Project → API → Webhooks
2. Create a new webhook:
   - **Name:** Vercel ISR Revalidation
   - **URL:** `https://<your-domain>/api/revalidate`
   - **Secret:** Same value as `SANITY_REVALIDATE_SECRET`
   - **HTTP method:** POST
   - **Trigger on:** Create, Update, Delete
   - **Filter:** Leave empty (all document types)

---

## 5. Sanity CORS Origins

Allow the production frontend to query Sanity directly.

1. Go to [sanity.io/manage](https://sanity.io/manage) → Project → API → CORS Origins
2. Add `https://<your-domain>` (with credentials if using authenticated requests)
3. If using a custom domain later, add that too

## 7. Sanity Studio Deployment

Deploy the Studio so content editors can access it from anywhere.

```bash
npm -w backend run deploy
```

This deploys to `https://<studio-name>.sanity.studio`.

---

## 8. Sanity Content Seeding

If the Sanity dataset is empty, seed it before going live:

```bash
npm run seed
```

Verify in Sanity Studio (`npm run studio` → http://localhost:3333) that all singletons and documents are populated.

---

## 9. Post-Deploy Verification

After the first successful Vercel deploy:

- [ ] Visit every page and confirm they render correctly
- [ ] Trigger initial AMPRE sync: `curl -X POST https://<your-domain>/api/ampre/sync -H "Authorization: Bearer <CRON_SECRET>"`
- [ ] Test draft mode: visit `/api/draft/enable?secret=<SANITY_PREVIEW_SECRET>`
- [ ] Verify cron job appears in Vercel dashboard → Cron Jobs tab
- [ ] Test contact form submission (requires Resend setup)
- [ ] Check `/sitemap.xml` and `/robots.txt` render correctly
- [ ] Test OG preview with https://opengraph.xyz or Twitter Card Validator

---

## 10. Custom Domain (Optional)

1. Go to Vercel → Project Settings → Domains
2. Add your custom domain
3. Configure DNS as directed by Vercel (CNAME or A record)
4. Add the custom domain to Sanity CORS origins (step 5)
5. Update `NEXT_PUBLIC_SITE_URL` env var to the custom domain

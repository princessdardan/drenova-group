## Codebase Patterns
- Sanity client config lives in `frontend/src/lib/sanity/client.ts` — exports `client`, `previewClient`, `projectId`, `dataset`, `apiVersion`
- `draftMode()` throws outside request scope (e.g., `generateStaticParams`) — always wrap in try/catch when used in shared fetch utilities
- Image URL builder lives in `frontend/src/lib/sanity/image.ts` — exports `urlFor(source)` function
- GROQ queries live in `frontend/src/lib/sanity/queries.ts` — shared projections keep queries DRY
- Listing projection maps `_id` → `id` and `slug.current` → `slug` to match frontend `Listing` type
- Ordered document queries use `| order(order asc)` — FAQ, CoverageArea, CompanyStat, CompanyValue, ValueProposition
- Team members ordered by `name asc`; parameterized queries use `$slug` and `$category`
- Use semantic tokens (bg-background, text-foreground) not raw colors
- `.env*` is gitignored at root level — env files go in `frontend/.env.local`
- All Sanity-specific types live in `frontend/src/types/sanity.ts` — import from `@/types/sanity`
- `isSanityImage()` type guard exported from `@/types/sanity` — use to narrow `string | SanityImage` union in components
- Image fields use union type `string | SanityImage` during migration — components use `isSanityImage()` to handle both
- Bio field uses union type `string | any[]` — check `typeof bio === "string"` before calling string methods
- Singleton GROQ queries use `*[_type == "typeName"][0]` — returns object, not array
- `homePageQuery` reuses `listingProjection` via `featuredListings[]->${listingProjection}` for consistency
- Fetch functions live in `frontend/src/lib/sanity/fetch.ts` — import from `@/lib/sanity/fetch`
- All fetch functions use `client.fetch<T>()` with `next: { tags, revalidate: 3600 }` for ISR
- Singleton fetchers return `T | null`; collection fetchers return `T[]`
- `getHomePage()` tags both `"homePage"` and `"listing"` since it dereferences featuredListings
- Use `createImageUrlBuilder` (named export) from `@sanity/image-url` — default export is deprecated
- Components use `isSanityImage()` guard → `urlFor(img).width(W).height(H).fit("crop").url()` for Sanity images, plain string fallback for URLs
- SanityImage `alt` field takes priority over generated alt text when available
- `PortableTextRenderer` component at `@/components/ui/portable-text` — wraps `@portabletext/react` with design system styling
- Singleton `_id` values match type names exactly: `siteSettings`, `homePage`, `aboutPage`, `buyPage`, `sellPage`
- `featuredListings` on homePage references listing IDs: `listing-1` through `listing-10` (6 active ones selected)
- Seed script at `scripts/seed-sanity.ts` — run via `npm run seed` with `SANITY_API_WRITE_TOKEN` env var
- Document IDs follow pattern: `listing-{n}`, `team-{slug}`, `testimonial-{n}`, `faq-{category}-{n}`, `coverage-area-{n}`, `company-stat-{n}`, `company-value-{n}`, `value-proposition-{n}`
- Page integration pattern: make component `async`, use `Promise.all` for parallel fetches, use `??` for hardcoded fallbacks when singleton is null
- Use `_id` from Sanity documents as React keys instead of array index
- Portable Text `any[]` types replaced with `PortableTextBlock[]` from `@portabletext/types` in `sanity.ts` and `team.ts`
